# LtBooks Ver 1.0 开发全路径

本文把「一个请求如何从浏览器走到数据库、一个功能应该改哪些文件、如何测试与打包」
讲清楚，供后续维护与二次开发使用。

## 1. 代码位置

| 层 | 路径 | 说明 |
| --- | --- | --- |
| 前端 | `/opt/ltbooks/web` | PHP 服务端渲染，`index.php` 为唯一入口；可由 `/var/www/ltbooks` 软链指向 |
| 后端 | `/opt/ltbooks/app` | Flask API、记账内核、AI 智能体、CLI 工具 |
| 报表与导出 | `/opt/ltbooks/storage` | 报表、导出 CSV、OCR 中间文件 |
| 票据附件 | `/opt/ltbooks/uploads` | 上传原件，PHP 鉴权后流式输出 |
| 备份 | `/opt/ltbooks/backups` | 完整备份与单文件滚动更新 |
| 数据库 | MariaDB，库名见 `LEDU_DB_NAME`（示例 `ltbooks`） | 50 张表 |
| 对外发布 | `<前端>/files/` | 文档与 `releases/` 三种安装包 |

两个仓库目录独立，但通过 HTTP + 内部令牌通信，可以分别部署到不同机器（需放通
后端端口并保证令牌一致）。

## 2. 整体调用链

```
浏览器
  │ GET /?p=invoices
  ▼
index.php
  ├─ 加载 lib/*（auth、i18n、ui、api、theme、version、help）
  ├─ 校验会话（lib/auth.php）
  ├─ 渲染页头与导航（$PAGES / $NAV）
  └─ include pages/invoices.php
          │ api_get('/invoices?...')
          ▼
   lib/api.php（curl；X-Ledu-Token / X-Ledu-Session / X-Ledu-Role / X-Ledu-User）
          ▼
   api.py（Flask，127.0.0.1:8099）
          ├─ 认证与角色校验
          ├─ core/reports.py、core/service.py、core/numbering.py 等
          └─ core/db.py（参数化 SQL、事务、错误翻译）
          ▼
       MariaDB
```

写操作统一在事务内完成；金额使用 `Decimal`，禁止浮点累加。报表金额只能由
`core/reports.py` 的确定性函数产出。

## 3. 前端结构

```
index.php              入口、路由表、导航、会话与语言初始化
lib/
  auth.php             登录、会话、权限、上传目录常量
  api.php              后端 HTTP 客户端与错误归一化
  ui.php               视图辅助：格式化、徽章、表格、分页、确认框
  i18n.php             语言选择与翻译函数 t()
  theme.php            8 套主题定义
  version.php          版本与构建号
  help.php             模块帮助内容
  lang/zh_hk.php       简中 → 繁中词典
  lang/en.php          简中 → English 词典
  zh_hk_auto.php       自动生成的繁中映射补充
pages/                 每页一个文件，按业务命名
assets/                app.css、图标、字体、交互脚本
```

页面约定：

- 页面只做展示与表单，不直接连数据库；
- 所有输出经 `e()` 转义；URL 参数与表单值先取值再校验；
- 金额显示用统一的 `money()`/格式化辅助，不手写小数位；
- 新增页面需要同时登记 `$PAGES`（标题、分组）、`$NAV`（入口）和
  `$SELF_HEAD`（若自渲染页头）。

## 5. 数据模型要点

- 所有业务表带 `entity_id`，支持多账套；干净包只含一个实体壳。
- 分录：`journal_entries` + `journal_lines`，借贷必须平衡；触发器与后端双重校验。
- 单据：报价、订单、发票、账单、贷记单、收付款共享编号规则与状态机。
- 外币：单据保存原币、汇率、功能货币金额；报表按功能货币汇总。
- 附件：`bill_attachments`、`expense_attachments` 等关联具体单据，文件落在上传目录。
- 设置：`app_settings` 存界面配置；`.env` 只保留启动必需项。
- 审计：`audit_log` 记录关键动作，并提供哈希链校验工具。

## 6. 金额与报表规则

1. 金额一律 `Decimal`，入库 `DECIMAL`，禁止二进制浮点；
2. 报表只读已过账分录，草稿单据不计入；
3. 期间解析集中在 `financial_analysis.resolve_period`，六种期间：
   `this_month`、`month`、`calendar_year`、`fiscal_year`、`inception`、`custom`；
4. 财务年按实体 `fiscal_year_end_mmdd` 计算；
5. AI 只生成定性文字，提示词明确禁止编造数字；模型不可用时回退确定性文案；
6. 报表导出 PDF/DOCX 时复用同一份取数结果，避免界面与文件数字不一致。

## 7. AI 与确认链

```
用户指令 / 票据
   ▼
doc_analyze（识别内容与业务性质）
   ▼
agents.actions（科目与单据建议）
   ▼
AI 动作记录（ai_actions，状态 pending）
   ▼
界面结果卡片 → 用户确认 → service 层写入 → 审计
```

- 智能体不能直接写库；`tools_write` 必须携带已确认的动作 ID；
- 票据识别会结合票面文字、往来单位和历史学习结果推断业务性质，缺失字段才提问；
- 移动端上传与桌面端共用同一识别接口；
- 随包 `agent/` 通过 `bridge/agent-bridge.mjs` 提供只读校验工具，部署到新机器无需
  外部路径。

## 8. 国际化

- 界面文案以简中为源，`t()` 按当前语言查词典；
- `lib/lang/zh_hk.php`、`lib/lang/en.php` 为人工维护词典；
- `lib/zh_hk_auto.php` 自动补充繁体，`lib/zh_hk_chars.php` 为逐字兜底；
- 后端 `core/i18n.py` 与 `core/lang_dict.json` 负责报表与文档文案；
- 年度报表包的 `MANIFEST` 文案在 `core/i18n.py` 的 `PACK_MANIFEST`；
- 新增文案必须同时补齐三种语言，否则界面会回落为简中（单据不允许混排）。

以下内容按规则**保留原文**，不参与翻译：公司法定名称、客户/供应商名、手工摘要、
单据编号、币种代码、HKFRS/HKAS 等准则名称。检查“零汉字”时应先排除这些业务原文。

检查工具：

```bash
python3 tools/scan_i18n.py --base https://<域名>
python3 tools/audit_pages.py https://<域名>
```

PDF 文字层核对（三语导出后只看固定文案是否混杂）：

```bash
env -u LD_LIBRARY_PATH pdftotext -layout <文件>.pdf - | head -60
```

三语 PDF 的自动化回归：

```bash
cd /opt/ltbooks/app && PYTHONPATH=. ./venv/bin/python -m unittest tests.test_pdf_i18n -v
```

## 9. 本地开发

后端：

```bash
cd /opt/ltbooks/app
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
cp .env.example .env          # 填数据库与令牌
./venv/bin/python api.py      # 默认 127.0.0.1:8099
```

前端：用任意 PHP 8.1+ 与 Nginx/Apache 指向 `index.php`，并设置：

```
LEDU_API_BASE=http://127.0.0.1:8099
LEDU_API_TOKEN=<与后端一致>
LEDU_UPLOAD_DIR=<上传目录>
```

修改后自检：

```bash
# PHP 语法（全部页面与 PDF 入口）
find /opt/ltbooks/web -name '*.php' -print0 | xargs -0 -n1 env -u LD_LIBRARY_PATH php -l
# 报表期间单元测试
env -u LD_LIBRARY_PATH php /opt/ltbooks/web/tests/report_period_test.php
# Python 编译与测试
cd /opt/ltbooks/app
./venv/bin/python -m compileall -q .
PYTHONPATH=. ./venv/bin/python -m unittest discover -s tests -p 'test_*.py'
node --check bridge/agent-bridge.mjs
```

> 本机需要 `env -u LD_LIBRARY_PATH`，否则 `php`、`pdftotext` 等会因
> `GLIBCXX_3.4.32 not found` 报错。

## 11. 构建与发布

```bash
cd /opt/ltbooks/app
./tools/build_release.sh
```

脚本行为：

1. 从**当前工作区**复制源码（不走 Git 历史），排除 `.env`、`venv`、`storage`、
   测试报告、旧文档与凭据；
2. 用 `mysqldump --no-data --routines --triggers` 导出 50 张表结构，导入时临时关闭
   外键检查以兼容建表顺序；
3. 仅导出 `entities`（一个公司壳）、`accounts`、`tax_rates`；
4. 生成 auto / manual 两个产物与 `.sha256`、`MANIFEST.txt`、`PACKAGE.json`；
5. 对全部 Shell、Python、PHP、Node 文件做语法检查。

安装包运行时的交互（`install.sh`）：

1. 询问域名或服务器 IP；
2. 域名部署时再询问 Let's Encrypt 证书通知邮箱（可留空，留空则用自签名 HTTPS）；
   纯 IP、`selfsigned`、`off` 模式跳过邮箱；`LTBOOKS_DOMAIN`、`LTBOOKS_SSL_EMAIL`
   可预先提供以跳过交互。

独立校验：

```bash
python3 tools/verify_release.py <包路径> [...]
```

校验项包括：归档路径安全、清单哈希、禁止文件、种子表白名单、密钥与私钥特征、
语法检查。

## 12. 常见改动指引

| 需求 | 改动位置 |
| --- | --- |
| 新增一个页面 | `pages/` 新建文件；`index.php` 登记 `$PAGES`、`$NAV`；补三语文案 |
| 新增界面文案 | 源码写简中，同时在 `lib/lang/zh_hk.php` 与 `lib/lang/en.php` 加词条；英文值不得含汉字 |
| 新增 PDF 固定文案 | `core/i18n.py` 加三语映射；单据用 `core/pdf.py`，报表用 `core/pdf_reports.py`；补 `test_pdf_i18n.py` 用例 |
| 新增报表 | `core/reports.py` 加确定性取数；`api.py` 加路由；`pages/report-*.php` 展示；报表中心加入口 |
| 新增单据类型邮件 | 详情页放「发送邮件」链接指向 `?p=email&docType=...`；后端 `email/doc-info` 与模板补类型 |
| 新增主题 | `lib/theme.php` 增加 preset（只覆盖颜色变量） |
| 新增智能体 | `core/agents/registry.py` 注册；提供提示词与只读工具；写入仍需确认 |
| 调整备份 | `core/backup.py` 与 `tools/auto_backup.py`；同步更新设置页说明 |
| 修改安装流程 | `tools/install.sh`；同步 `tools/package-readme.md` 与本文档；改动域名/邮箱提示后重跑交互与非交互用例 |

## 13. 编码约定

- 文件头保留版权与 SPDX 标识；
- 注释解释「为什么」，不复述代码；
- SQL 全部参数化，动态表名/列名必须白名单；
- 用户输入在入口校验，输出统一转义；
- 不在代码中写死生产域名、目录、密钥或第三方服务地址；
- 新增依赖需固定版本并更新 `requirements.txt`；
- 金额、税额、报表不得由模型生成。
