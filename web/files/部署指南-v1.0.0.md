# LtBooks Ver 1.0 部署指南

适用于两种发布包：自动化部署包、人工部署包。所有包共用同一份源码与
安装脚本，差异只在系统层动作和是否接入模型辅助排错。

第 12 节给出单机集中部署的参考基线（服务名、路径与参数），排查该布局的问题时以该节为准。

## 1. 环境要求

| 组件 | 最低版本 | 说明 |
| --- | --- | --- |
| 操作系统 | Debian 12 / Ubuntu 22.04+ | 自动模式按 apt 安装；RHEL 系建议使用手动模式 |
| Nginx | 1.18+ | 提供 HTTPS 与 PHP 转发 |
| PHP | 8.1+（推荐 8.3） | 需 `curl`、`mbstring`、`xml` 扩展；`gd` 可选 |
| PHP-FPM | 与 PHP 同版本 | 使用独立 pool 与 socket |
| Python | 3.10+（推荐 3.12） | 后端与安装脚本 |
| Node.js | 18+（推荐 20） | 随包会计校验智能体；自动模式可自动安装 20 |
| MariaDB | 10.6+（推荐 10.11） | 字符集 `utf8mb4` |
| 其他 | openssl、rsync、curl | 证书、同步、下载 |

建议配置：2 核 / 4 GB 内存 / 20 GB 磁盘；有 OCR 与 PDF 导出需求时预留字体与
WeasyPrint 依赖的磁盘空间。

## 2. 包的组成

两种包结构相同，只有安装入口不同：

```
LtBooks-Ver1.0-<variant>-<date>/
├── install.sh                 自动化安装入口（auto 包）
├── install-manual.sh          人工安装入口（manual 包）
├── backend/                   Python 后端与随包智能体
├── frontend/                  PHP 前端
├── sql/01-schema.sql          50 张表、触发器、例程（无业务数据）
├── sql/02-master-data.sql     公司实体壳、108 科目、12 税率
├── LICENSE / README.md / MANIFEST.txt / PACKAGE.json
└── docs/                      本指南、HOWTO、开发全路径、发布说明
```

安装脚本会计算 `MANIFEST.txt` 中每个文件的 SHA-256；发布目录另有整包 `.sha256`。

## 3. 自动化模式

适用：全新 Debian 12 / Ubuntu 22.04+ 服务器，可联网，以 root 运行。
**输入域名或服务器 IP；域名部署时再填证书通知邮箱（可留空）**，安装器自动检查并安装全部依赖。

```bash
sudo ./install.sh
```

交互提示：

```text
请输入要部署的域名或服务器 IP（例如 finance.example.com 或 203.0.113.10）：
> finance.example.com

请输入用于 Let's Encrypt 证书通知的邮箱（可留空，留空则使用自签名 HTTPS）：
> admin@example.com
```

邮箱用于证书到期提醒；留空继续使用自签名 HTTPS。纯 IP 部署不会询问邮箱。

非交互环境用环境变量提供：

```bash
sudo LTBOOKS_DOMAIN=books.example.com LTBOOKS_SSL_EMAIL=admin@example.com ./install.sh
```

可覆盖的参数：

| 变量 | 默认值 |
| --- | --- |
| `LTBOOKS_DOMAIN` | 交互输入；非交互时必填 |
| `LTBOOKS_SSL_MODE` | `auto`（域名+邮箱走 certbot，否则自签名） |
| `LTBOOKS_SSL_EMAIL` | 交互输入（可留空） |
| `LTBOOKS_APP_DIR` | `/opt/ltbooks` |
| `LTBOOKS_WEB_ROOT` | `/var/www/ltbooks` |
| `LTBOOKS_UPLOAD_DIR` | `/var/lib/ltbooks/uploads` |
| `LTBOOKS_BACKUP_DIR` | `/var/backups/ltbooks` |
| `LTBOOKS_DB_HOST` / `PORT` | `127.0.0.1` / `3306` |
| `LTBOOKS_DB_NAME` / `USER` | `ltbooks` / `ltbooks_app` |
| `LTBOOKS_DB_PASSWORD` | 随机 48 位十六进制 |
| `LTBOOKS_WEB_USER` | 自动探测 `www-data` / `nginx` / `apache` / `www` |

例：

```bash
sudo LTBOOKS_DOMAIN=books.example.com \
     LTBOOKS_SSL_EMAIL=admin@example.com \
     ./install.sh
```

执行后：

```bash
systemctl status ltbooks-api
systemctl list-timers ltbooks-backup.timer
nginx -t
php-fpm8.3 -t
```

自动化模式会创建：

- 系统用户/组 `ltbooks`（服务运行账号），并把 Web 账号加入该组；
- `/etc/php/<ver>/fpm/pool.d/ltbooks.conf` 独立 pool，socket `/run/php/ltbooks.sock`；
- `/etc/nginx/sites-available/ltbooks.conf`（或 `conf.d/ltbooks.conf`）；
- `/etc/systemd/system/ltbooks-api.service`；
- `/etc/systemd/system/ltbooks-backup.{service,timer}`，timer 每分钟调用一次 tick，
  具体时间由界面「自动备份设置」决定（香港时间，默认 09:00、17:00）；
  自动备份为单文件滚动更新，手动备份为完整备份。

### 3.1 域名与 IP

| 输入 | HTTPS | 说明 |
| --- | --- | --- |
| 已解析到本机的域名 + 邮箱 | Let's Encrypt 公开证书 | 浏览器直接受信 |
| 域名 + 邮箱留空 | 自签名证书 | 首次访问需手动信任；之后可用 `LTBOOKS_SSL_EMAIL` 重新申请 |
| 纯 IP | 自签名证书 | Let's Encrypt 不支持纯 IP；绑定域名后重新运行并设置 `LTBOOKS_SSL_EMAIL` 即可申请公开证书 |

交互安装会在域名之后询问一次证书通知邮箱；纯 IP 或 `selfsigned`/`off` 模式不询问。

## 4. 人工模式

适用：已有面板的主机、内网或需要自行控制系统软件版本的环境。**系统环境由人工安装**，
`install-manual.sh` 只部署应用。

### 4.1 人工安装环境

以 Debian / Ubuntu 为例，完整命令见 [HOWTO.md](HOWTO.md) 第 2.1 节。最低版本：

| 组件 | 最低 |
| --- | --- |
| PHP | 8.1（扩展 curl、mbstring、xml、pdo_mysql） |
| Python | 3.10 |
| Node.js | 18 |
| MariaDB | 10.6 |

### 4.2 部署应用

```bash
unzip LtBooks-Ver1.0-manual-clean-<date>.zip
cd LtBooks-Ver1.0-manual-clean-<date>
./install-manual.sh
```

只做：创建目录、建库导表、创建管理员、安装前后端、生成示例配置。不安装系统软件、
不创建系统账号、不启动服务、不修改面板配置。

安装后在 `<应用目录>/setup/` 得到：

- `nginx-ltbooks.conf.example`
- `php-fpm-ltbooks.conf.example`
- `ltbooks-api.service.example`
- `ltbooks-backup.service.example` / `.timer.example`
- `ssl/fullchain.pem`、`ssl/privkey.pem`（自签名兜底）

接入面板时注意：

1. PHP-FPM pool 的 `user` / `group` 必须与读取上传目录的 Web 账号一致；
2. 站点根目录指向前端目录，`/files/` 必须拒绝访问；
3. 上传目录不放在 Web 根目录；
4. 以 root 运行安装器时，若未指定 `LTBOOKS_WEB_USER`，会选用系统中已存在的
   Web 账号；以普通用户运行时默认使用当前账号。

启动后端：

```bash
<应用目录>/venv/bin/python <应用目录>/api.py
```

或使用 `setup/ltbooks-api.service.example` 注册服务。

## 5. HTTPS

- `LTBOOKS_SSL_MODE=auto`：有域名与邮箱时用 Certbot 申请，否则自签名；
  交互安装会在域名后询问证书通知邮箱（可留空）；
- `certbot`：强制申请公开证书，失败即报错（邮箱必填）；
- `selfsigned`：只生成本地证书，适合内网验收；
- `off`：仅 HTTP。**不推荐**：会话 Cookie 带 `Secure`，HTTP 下无法登录。

证书路径：自动模式 `/etc/ssl/ltbooks/`；手动模式 `<应用目录>/setup/ssl/`。

## 7. 运行时配置（.env）

安装器生成，权限 600/640。关键项：

| 键 | 用途 |
| --- | --- |
| `LEDU_DB_*` | 数据库连接 |
| `LEDU_API_HOST` / `PORT` | 后端监听，默认 `127.0.0.1:8099` |
| `LEDU_API_TOKEN` | 前端到后端的内部令牌，≥32 位随机串 |
| `LEDU_WEB_ROOT` | 前端目录，供 PDF/Logo 读取 |
| `LEDU_STORAGE_DIR` | 证书、临时文件等应用数据 |
| `LEDU_UPLOAD_DIR` / `LEDU_UPLOAD_DIRS` | 票据附件目录（可多路径） |
| `LEDU_BACKUP_DIR` / `KEEP` / `LOCK` | 备份目录、保留天数、锁文件 |
| `LEDU_AGENT_PRESET` | 随包会计校验智能体目录 |
| `LEDU_NODE_BIN` | Node 可执行文件 |
| `LEDU_LLM_*` | 模型接口，界面设置优先 |
| `LEDU_VISION_API_KEY` | 视觉/OCR 接口 |
| `LEDU_SMTP_*` | 邮件，界面设置优先 |

修改 `.env` 后需重启后端：`systemctl restart ltbooks-api`。

## 9. 从旧环境迁移

1. 旧环境「备份与恢复」创建备份并下载；
2. 新服务器安装干净包（同一版本）；
3. 新环境「备份与恢复」上传并恢复；
4. 复制旧 `.env` 中的模型、SMTP 与令牌配置，或在新界面重新填写；
5. 校验客户/供应商数量、最近一期报表与备份前一致。

## 10. 卸载

```bash
systemctl disable --now ltbooks-api ltbooks-backup.timer
rm -f /etc/systemd/system/ltbooks-api.service /etc/systemd/system/ltbooks-backup.*
rm -f /etc/nginx/sites-enabled/ltbooks.conf /etc/nginx/sites-available/ltbooks.conf
rm -f /etc/php/*/fpm/pool.d/ltbooks.conf
systemctl reload nginx && systemctl restart 'php*-fpm'
```

数据目录（`/opt/ltbooks`、`/var/lib/ltbooks`、`/var/backups/ltbooks`）在确认已备份后
再删除；数据库用 `DROP DATABASE ltbooks;` 清理。

## 11. 常见问题

| 现象 | 处理 |
| --- | --- |
| `Missing PHP extension` | 安装对应扩展后重试；仅 `curl`、`mbstring`、`xml` 为必需 |
| `Node.js 18 or newer is required` | 自动模式会安装 Node 20；手动模式请先升级 |
| Nginx 启动失败 | `nginx -t`；确认 socket 路径与 PHP-FPM pool 一致 |
| 502 | 后端未启动或端口不同；`systemctl status ltbooks-api` |
| 登录循环 | 未启用 HTTPS |
| 上传 413 | 调大 Nginx `client_max_body_size` 与 PHP `upload_max_filesize` |
| 证书不受信任 | 自签名属预期；生产请配置真实证书 |

## 12. 单机集中部署基线（示例）

以下是一个单机集中部署的参考基线。数值取自真实运行环境，涉及域名、库名等已替换为
示例值；用于说明「所有组件装在一台机器、共用同一套目录」时的实际配置形态。

安装包默认把前端放在 `/var/www/ltbooks`，本节示例则把所有内容集中在 `/opt/ltbooks`，
两者都可用，排障时请先确认自己属于哪种布局。

### 12.1 路径与服务

| 项目 | 示例值 |
| --- | --- |
| 应用根 | `/opt/ltbooks`（`app/`、`web/`、`storage/`、`uploads/`、`backups/`、`archive/`） |
| 前端站点 | `/opt/ltbooks/web`；可由 `/var/www/ltbooks` 软链指向 |
| 域名 | `finance.example.com` |
| 后端服务 | `ledu-api.service` → `127.0.0.1:8099` |
| 后端日志 | `/var/log/ledu-api.log` |
| Web 服务器 | Nginx；站点配置 `/www/server/panel/vhost/nginx/finance.example.com.conf` |
| PHP | 8.3，FPM pool `www`（`/etc/php/8.3/fpm/pool.d/www.conf`） |
| 数据库 | MariaDB `ltbooks`，用户 `ltbooks`，`127.0.0.1:3306` |
| 证书 | Let's Encrypt，有效期至 2027-02-17，acme.sh 自动续期 |

### 12.2 关键参数

```ini
; /etc/php/8.3/fpm/pool.d/www.conf
pm = dynamic
pm.max_children = 20
pm.start_servers = 5
pm.min_spare_servers = 5
pm.max_spare_servers = 10
```

原值为 `5 / 2 / 1 / 3`，2026-11-21 因出现 `server reached pm.max_children`
告警上调。修改后执行 `systemctl reload php8.3-fpm`。

```ini
; /etc/logrotate.d/ledu-api
/var/log/ledu-api.log {
    su root root
    daily
    rotate 14
    missingok
    notifempty
    compress
    delaycompress
    copytruncate
    create 0640 root root
}
```

`su root root` 是因为 `/var/log` 为 `root:syslog 775`；`copytruncate` 保证
不重启后端。

### 12.3 自动备份

线上用系统 crontab，每分钟由 `flock` 互斥调用一次 `tick`：

```cron
* * * * * /usr/bin/flock -n /var/run/ltbooks-auto-backup-tick.lock \
  /usr/bin/env -u LD_LIBRARY_PATH \
  /opt/ltbooks/app/venv/bin/python /opt/ltbooks/app/tools/auto_backup.py tick \
  >> /opt/ltbooks/backups/auto-backup.log 2>&1
```

调度时间存于 `settings` 表的 `backup.schedule`，默认香港时间 09:00 / 17:00；
保留 180 份（`LEDU_BACKUP_KEEP`）。首次必须先建立完整基线：

```bash
cd /opt/ltbooks/app && ./venv/bin/python tools/auto_backup.py create --full
```

### 12.4 部署后验证

```bash
systemctl is-active nginx php8.3-fpm ledu-api cron
curl -fsS http://127.0.0.1:8099/health
curl -fsS -o /dev/null -w '%{http_code}\n' https://finance.example.com/
crontab -l | grep auto_backup
ls -lh /opt/ltbooks/backups/
```

```bash
# 后端回归
cd /opt/ltbooks/app && PYTHONPATH=. ./venv/bin/python -m unittest discover -s tests -p 'test_*.py'
# 前端语法
find /opt/ltbooks/web -name '*.php' -print0 | xargs -0 -n1 env -u LD_LIBRARY_PATH php -l
```

期望：服务 `active`、`health` 200、首页 200、cron 命中 1 条、备份目录至少一份
`tar.gz`、131 个后端用例通过、PHP 语法零失败。

> 本机命令需要 `env -u LD_LIBRARY_PATH` 前缀，否则某些二进制会因
> `GLIBCXX_3.4.32 not found` 失败。
